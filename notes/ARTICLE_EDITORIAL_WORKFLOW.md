# 公众号关系长文：研究、扩充与编辑流程

更新：2026-10-11。服从 BRAND_POSITIONING.md；公众号长文在 MULTIFORMAT_CONTENT_SYSTEM.md 下走本流程。视频仍走原视频路线。

## 本次纠偏

用户经历是文章入口，不是全文素材上限。不能把口述整理得通顺，就当成已完成内容创作。扩充应增加读者理解、具体情境和行动选择，不能靠重复感慨、填字数或堆研究结论。

选题已确认后，Agent 自动研究、组织材料、形成大纲并推进用户已授权的写作。只有改变核心选题、替作者增加重大立场或缺少不可替代的亲历事实时才提问。仅请求方法研究时交付方法与诊断，不擅自重写全文。

## 1. 恢复原题，诊断缺什么

先读用户最初确认的读者问题，再读最新补充。后补的礼物、孩子、惜时感受等细节不能自行取代原题。

已有失败成稿时，先定位：题偏了、主线散了、材料薄了、推进平了、表达假了。缺结构先重建结构；缺材料先研究；不直接整体润色。

在内容简报中记录：具体读者及处境、一个核心问题、一句话主张、相对常见说法新增什么、读者读后能理解或尝试什么。未被用户表达过的个人立场不得伪装为他的原有想法。

## 2. 研究两种材料

### 读者和同类文章

使用 Agent Reach 与 Creator Buddy 的公众号样本能力。关键词要贴具体困惑，不只搜“情感”。先查近期，再按材料不足原因扩大日期或查常青内容。默认精读约 3 篇可访问的相邻文章，不为凑数纳入不相关作品。

记录链接、日期、作者、完整正文是否取得、可见阅读/分享/评论及口径。只有标题或摘要时只能分析选题与标题，不能声称拆过全文。缺互动数据时称参考样本，不称已验证爆款。同题多只证明供给频率，读者需求仍要结合问题与反馈判断。

每篇按以下字段拆解：

- 标题承诺：对谁说、触及什么困惑、正文是否兑现。
- 开头：具体从哪件事进入，何时让读者看见自己的处境。
- 章节：逐节写出功能与新增信息，而非只抄小标题。
- 材料：故事、对话、解释、建议如何交替，哪里最充分。
- 共鸣：哪一句或哪个场景可能让人认出自己；这是编辑判断，不冒充实测因果。
- 结尾：落在哪里，为什么读者可能愿意转发给某个人。
- 可借与缺口：只迁移组织方法；不搬运句子、人物故事、立场与私生活。

### 为文章补材料

从大纲缺口出发检索，优先补具体公开案例、读者公开讨论、可核验的生活实践、相关书籍原文。研究只在确有解释价值时使用，不把“带论文”作为深度标准。

材料分为：用户明确提供的经历；可追溯公开资料；有依据的分析；建议话术/假设示例。建议话术用“可以试着说”等自然表达，不伪装成当事人说过的话。假设示例不能作为证明普遍规律的真实案例。

不得编造作者朋友、妻子的咨询案例、现场对话、具体礼物或心理活动。公开材料找得到就由 Agent 自己补，不把全部研究工作转交用户。

## 3. 扩充的是内容，不是篇幅

对每个重要判断，按需要补其中一两项：

- 具体处境：读者到底卡在什么时刻。
- 原因解释：为什么这样一句话或一次安排容易卡住。
- 对照：两种做法怎样改变谈话与关系，而非给人贴好坏标签。
- 可用表达：可以怎么开口、怎样跟进，给不机械的示例。
- 实施条件：忙、异地、带孩子等现实因素怎样改变做法。
- 真正反例：若只有一方持续回应，这个建议需怎样调整。

这些是编辑工具，不要求每节填满。没有新材料、新解释或新选择的扩写，删除。

## 4. 先做有层次的章节，再写正文

关系长文通常以一个具体矛盾开场，用 3—4 个有含义的小标题推进；数量服从内容，不固定套模板。即使不到 2000 字，只要有多层论述也应分节。

大纲逐节写：读者的问题 → 本节判断 → 支撑材料及出处 → 新增收获 → 与下一节的关系。节与节不能只是同一观点换说法。给重点章节更多篇幅，字数预算是篇幅分配工具，不是硬凑字数任务。

建议以“读者如何从困惑走到可行动”组织，不按素材提供顺序拼接。小标题独立阅读时，应能看出全文推进；避免“珍惜当下”“学会沟通”等空标签。

## 5. Gemini 初稿与逐节审稿

把品牌约束、已确认主题、材料包、章节任务及读者收获直接交给当前可用的 Gemini 生成初稿；不先由主 Agent 写研究说明文再让模型润色。保留原始初稿。

审稿顺序：

1. 回答原题了吗？标题与正文是否一致？
2. 每节给了什么新东西？例子是否足够支撑判断？
3. 是否写到读者真实处境，是否有因果解释而非只有情绪标签？
4. 是否能照着尝试，而非只有“主动一点”“多联系”？
5. 亲历、引语和事实是否准确？建议是否被写成保证？
6. 手机阅读分段是否清楚，段落轻重与过渡是否自然？
7. 最后做 deai-promax 清理，保留具体内容，不为了检测分数反复改写。

最多两轮集中修订；未解决的内容问题如实记录。禁止以机器评分、字数达标或结构齐全冒充文章好看。正文不用研究流程、责任说明和模型限制撑篇幅，不强制独立“边界”章节，不强行升华。

## 6. 交付与复盘

一期只有一个明确标记的当前审阅稿，原始初稿与历史稿保留但不混称 final。研究与审稿在后台，正文可独立阅读。文章通过用户审阅后再提炼卡片和视频，不把每段直接切成一页。

目录沿用 episodes/<日期 主题>/article/；新增文件可为研究提要.md、大纲.md、正文.md、审稿记录.md。事实来源保存 research/<主题>/。发布只在另获授权后执行；真实反馈用于改进，不推测必爆。
