# 视频方法论融合说明

本文件服从 `notes/BRAND_POSITIONING.md`。生产方法服务于“余光所及｜有解”的品牌母题，不反过来决定账号做什么。

本项目不是把四个仓库的步骤简单叠加，而是把它们放在不同决策层：

| 层 | 采用的方法 | 本项目的落地物 | 门禁 |
| --- | --- | --- | --- |
| 选题入口 | `notes/TOPIC_SELECTION_SYSTEM.md`（融合 Simon 上集 + Jessi 七模型 + Creator Buddy `space-video-topic` + 品牌母题） | `research/<期>/选题卡.md`、`爆款拆解.md` | 现实触发/高频问题、明确读者、单一交付、同赛道样本、证据、机制/规则、人之处境必须说清 |
| 事实与边界 | Simon 五道内审 + `video-common` | `事实链.md`、来源台账 | 核心判断有原始出处；推断和未知分开 |
| 口播结构 | Gemini 初稿 + Hook → 事件/机制推进 | `旁白稿.md`、`scenes.js` | 先讲一件值得看完的事；不写搜索说明、责任边界或解释性免责声明 |
| 视觉机制 | `huashu-art-motion` 的“先设计一帧、让画活” | `素材覆盖表.md`、场景代码 | 每个镜头有主动作；不拿装饰动画冒充解释 |
| 解释语法 | 白板 / 3B1B / 财经图表按内容选择 | `scenes.js` | 机制用路径、节点、时间轴；数字从来源来 |
| 渲染与审片 | `whiteboard-video` + Huashu QA | `build/`、抽帧检查、机器检查 | 字幕区、水印区、静止帧、异常跳变逐项验收 |
| 发布与复盘 | `gbro-cover-design`、`dbs-title-cover-intro`、`dbskill` | `发布.md`、封面提示词、复盘记录 | 标题/封面/开头共用同一承诺；发布后只测一个变量 |

## Creator Buddy 接入

Creator Buddy 的复用规则、安装源、样本拆解字段、平台操作和视频 Beat 门禁统一见 [`notes/CREATOR_BUDDY_ADAPTER.md`](CREATOR_BUDDY_ADAPTER.md)。写稿前先拆同赛道样本；样本只迁移抽象机制，不复制原句、人物、镜头顺序和视觉指纹。

## 选题机制落地

本项目不把“品牌母题”当作凭空发散题目的理由。品牌提供观察角度，选题机制负责从现实问题中找到值得做、现在做、做得出来的题。

候选题先经过：

1. 现实触发或高频问题；
2. 读者、场景和具体困惑；
3. 一个可兑现的主要结果；
4. 原始材料和证据缺口；
5. 五个内审门禁与五个标题入口；
6. 与品牌机制、规则和人的处境的连接；
7. 可执行的证据画面、机制动画或故事场景。

完整字段、热点型与常青型的差异、用户拍板前的停点以及复盘假设，统一以 [`notes/TOPIC_SELECTION_SYSTEM.md`](TOPIC_SELECTION_SYSTEM.md) 为准。

## 生产顺序

1. 创意/话题：先按 `notes/TOPIC_SELECTION_SYSTEM.md` 形成候选选题卡，再用品牌母题判断“世界怎么运转”或“规则中的人”在哪里。
2. 同赛道拆解：按 Creator Buddy 记录参考样本的前 0—3 秒、前 3—10 秒、节奏、口播、画面和结尾。
3. Gemini 初稿：把已批准的选题卡和拆解报告交给本机 Gemini CLI，直接生成面向平台观众的初始口播；主 Agent 不先写研究说明。
4. 保真事实核对：只检查数字、因果、术语、来源和表达强度，不把免责声明塞回口播。
5. 事实链：先查官方材料，再决定能讲到哪一层；材料不足就缩小命题。
6. 口播：围绕一个事件、机制或规则推进，不做知识清单，不做儿童老师口吻，不做成人鸡汤。
6. 风格选择：机制用 t1/y3，证据用 y2，产品 UI 用 t2，真实数据用 t3，规则实验可用 H3；新闻才优先真实图片/视频。
7. 素材覆盖：每段旁白必须有主视觉、证据或机制图；没有覆盖就不渲染整片。
8. Visual Master Sheet：为每段确定构图、主体、动作、来源、安全区和“解解”是否出现。
9. Single-shot Shot Pack：把每段的动作和时长写成代码/H3 可执行的镜头输入。
10. TTS/字幕/渲染：先跑样片和静帧，再整片。
11. QA/交付：检查事实、声画、阅读时间、画面运动和发布字段；不自动公开发布。

## 已停止实验的单期取舍

- 主题是常青的机制解释，不是假装成 72 小时热点；“时效性”门禁改为检查资料版本和当前产品口径。
- 采用“规则型 + 白板/动态路径图”：核心是说明一条路线如何被按路段、按未来进入时刻逐段推演。
- 不声称掌握高德内部全部模型，也不声称每次都准确；公开材料能证明机制，不足以证明全场景准确率。
- 首期先用 Edge TTS 跑通画面和时间轴，正式发布前替换为已配置的火山 TTS 2.0 音色并重新生成字幕时间戳。
