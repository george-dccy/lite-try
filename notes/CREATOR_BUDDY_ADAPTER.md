# Creator Buddy 能力接入说明

本文件记录本项目对 `SpaceZephyr/creator-buddy` 的实际复用方式。源仓库版本：`edf46c567ff54b72ee2157d06f3a02dbd67aaa9c`，地址：[SpaceZephyr/creator-buddy](https://github.com/SpaceZephyr/creator-buddy)。

项目已安装 Creator Buddy，位于 `.agents/skills/`。自 2026-10-11 起扩展为一题多种内容：同时复用公众号文章写作、小红书标题与配文、图文分页、视频脚本及样本分析，具体路由见 MULTIFORMAT_CONTENT_SYSTEM.md。科技专用配色与标题不作为关系赛道默认。

## 一、复用的上游能力

| Creator Buddy 能力 | 本项目复用内容 | 本项目交接物 |
| --- | --- | --- |
| `space-video-topic` | 参考样本 → 选题 → 钩子 → 标题 → 正文的前端链路；先拆爆款再写 | `research/<期>/爆款拆解.md`、`选题卡.md`、`标题候选.md` |
| `space-video-script` | 前 3 秒钩子、口语化短句、逐秒分镜和声画交接 | `episodes/<期>/script.md` |
| `space-video-broll` | 先找运动隐喻，再排连续 Beat；反 PPT；至少 80% Beat 有真实状态变化 | `episodes/<期>/broll-plan.md`、代码动画 |
| `space-video-cover` | 账号家族气质固定，单条封面重新设计；封面短钩子和视频标题分开 | `episodes/<期>/cover-brief.md` |

## 二、写稿前必须完成的爆款拆解

只要有可访问的同赛道样本，Gemini 写稿前必须先完成一份拆解。样本优先选择：同主题或相邻主题、同平台或相近平台、近期有明确传播信号的内容；不能只找“看起来像”的标题。

每条样本至少记录：

1. 链接、平台、作者、发布时间和可核验的播放/互动数据；
2. **前 0—3 秒**：第一句话、画面动作、冲突/结果/问题、信息缺口；
3. **前 3—10 秒**：承诺是否兑现、是否继续加码、观众为什么不划走；
4. **节奏**：每个 Beat 的时长、信息点密度、转场和证据出现的位置；
5. **口播风格**：句长、停顿、口语词、自问自答、情绪强度和段尾推进方式；
6. **视频设计**：真实素材、录屏、截图、数据图、代码动画、人物出镜和 B-roll 的比例；
7. **结尾**：结论、反问、下一步动作或系列钩子；
8. 可迁移的抽象机制、不可复制的身份/资源/账号优势，以及本项目的空位。

拆解只迁移结构和机制，不复制原句、人物、镜头顺序、视觉指纹或未经核实的数据。

## 三、从爆款样本到本项目选题

1. 先按 [`TOPIC_SELECTION_SYSTEM.md`](TOPIC_SELECTION_SYSTEM.md) 找现实触发、高频问题或规则变化。
2. 用 `space-video-topic` 的“热点型 / 领域型 / 收藏型 / 经验型”判断入口，不把平台热度直接等同于品牌适配。
3. 把爆款样本的开头、节奏和读者承诺写入候选卡，但仍要通过本项目的读者、交付、时机、证据、脱水、品牌和视觉门禁。
4. 用户拍板后，把拆解报告作为 Gemini 的输入约束：只告诉它要借鉴的抽象结构、口吻和节奏，不要求模仿某条视频。
5. Gemini 直接生成面向平台观众的初始口播；主 Agent 只做事实核对、最小保真修正和后续制作交接。

## 四、标题与开头

标题执行 `baokuan-title-generator` 的顺序：

1. 先写内容简报：核心对象、核心变化、读者价值、证据、冲突、时效和事实边界；
2. 生成 10—12 个候选，至少覆盖 6 种不同方法；
3. 按内容兑现度、读者相关性、具体性、好奇缺口、收益/后果、情绪冲突、清晰节奏、独特性评分；
4. 输出综合首选、稳健版、传播版、搜索版和实验版；
5. A/B 每次只改一个变量，发布后只观察一个假设；
6. 视频标题、封面短文案和开头口播必须共同兑现同一个承诺。

前 3 秒执行 `space-video-topic` 与 `space-video-script` 的交接：第一句必须立即进入场景、冲突、反常识或结果，不先介绍账号、不解释研究过程、不用抽象预热。准确话术从参考样本拆解和 Gemini 初稿中产生，不由本文件预先编造固定句式。

## 五、画面与动效

`space-video-broll` 的关键约束直接纳入本项目：

- 先写一句“这条视频靠什么视觉隐喻从什么状态变成什么状态，证明什么主张”；
- Beat 是连续时间轴，不是多张静态卡片；
- 至少 80% 的 Beat 必须有生长、聚合、坍缩、路径绘制、替换、变形或点亮等真实状态变化；
- 文字是锚点，不是主角；
- 不使用 Emoji，优先用几何形状、SVG 线性图标、截图和证据卡；
- 机制内容优先使用 `blueprint-grid`、`minimal-light` 或适配题材的真实素材/代码动画；不默认白板；
- H3 只执行已定稿的时间和动作，不重写故事、不生成文字、不新增规则。

## 六、平台素材与实测

关系赛道的对标还须按 BRACKET_NARRATIVE_FORMAT.md 筛选：互动看近期分布，不用单篇高赞代表账号常态；广告露出与成交分开记录；私信引导或招募留言只能证明承接意图。确定对标后抽取方法，再用括号叙事重做封面、分页与人物，不能把对方成套图文当模板。

- 需要手机 App 的画面或数据：启动安卓模拟器，按真实路径操作并录屏；记录设备、版本、入口、时间和看到的数值。
- 需要浏览器内容：使用 computer use 在真实可见页面中操作，保留页面上下文和来源截图；不把搜索结果摘要当作页面原文。
- 需要参考视频：使用当前可用的 `agent-reach` 路由和视频 references 下载或转写；先保存字幕/逐字稿，再按需保存视频；不绕过验证码、登录、权限、付费墙或 DRM。
- 公开平台数据必须保留原始链接、访问日期和数据口径；拿不到互动数据就明确写“未获取”，不估算。

## 七、当前项目的最终流水线

以下为视频分支。公众号长文分支按 `notes/ARTICLE_EDITORIAL_WORKFLOW.md` 执行：文章样本与读者问题研究 → 主张与材料扩充 → 有轻重的章节大纲 → Gemini 初稿 → 逐节编辑 → 去 AI 味 → 标题与排版。不得以视频前几秒拆解替代公众号全文分析。

```text
热点/高频问题
  → Creator Buddy 样本搜索
  → 同赛道爆款拆解（开头/节奏/口播/画面）
  → 项目选题卡与品牌/证据门禁
  → 用户拍板
  → Gemini 初始口播
  → 事实核对 + deai-promax
  → 标题矩阵 + 封面短钩子
  → Visual Master Sheet
  → Single-shot Shot Pack / B-roll Beat
  → 实测录屏、真实素材、代码动画、H3
  → Huashu 配音、字幕、渲染和验收
  → 发布后单变量复盘
```
