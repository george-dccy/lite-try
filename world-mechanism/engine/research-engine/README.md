# Research Engine v0.2

研究不是一个单独阶段，而是一条贯穿“理解 → 创作 → 生产”的证据轨。

## Pass A — Premise Check

### 什么时候做
发生在 Mechanism Explorer / Creative Gate 之前，尤其适用于：
- 历史；
- 科学；
- 技术；
- 社会热点；
- 依赖具体制度、数字、日期的题。

### 只解决五件事
1. 核心术语是什么意思？
2. 核心前提是否真实？
3. 日期、地域、人群、制度范围是否混淆？
4. 是否存在会推翻当前机制模型的替代解释？
5. 哪些内容必须标 H，而不是 F？

### 输出
- minimal source ledger；
- premise verdict；
- scope / date；
- F / I / H / R；
- evidence gaps。

Pass A 的目标是防止基于错误前提做出漂亮创意，不是搜集越多越好。

---

## Pass B — Evidence Pack

### 什么时候做
Creative Blueprint 已经形成、准备进入 Content Master 之前。

### 目标
让大胆创意建立在足够可靠、可追溯的事实底座上。

### 来源优先级
1. 官方原件 / 原始论文 / 法规 / 档案 / 财报 / 原始采访
2. 高质量专业媒体与权威二手资料
3. 专家解释与教科书
4. 社区讨论仅用于发现问题和体验，不单独支撑关键事实

### 输出
- claim ledger；
- source ledger；
- key facts；
- competing explanations；
- uncertainty；
- dates / scope / population；
- claims that must not be strengthened；
- facts useful for visualization；
- archival / visual asset candidates。

---

## 四层标签
- **F Fact**：可核验
- **I Interpretation**：解释
- **H Hypothesis**：待验证
- **R Fictional Rule**：主动创作规则

研究 Agent 不允许把 H 自动升级为 F，也不能因为叙事需要替用户选择争议结论。

---

## 当代 / 动态主题

必须记录：
- checked_at；
- 数据对应时间；
- 适用平台 / 人群；
- 哪些内容可能快速变化。

“最新”不是一个永久事实。

---

## 历史主题

必须分离：
- 当时发生的事实；
- 后来的制度化结果；
- 后人解释。

例如：
**1883 铁路采用标准时间** 与 **1918 美国联邦标准时间立法** 是不同事件，不能因为故事顺滑合并。

---

## 研究退出条件

当继续查资料已经：
- 不改变 Mechanism Map；
- 不改变 Blueprint；
- 不改变 claim strength；
- 不增加关键可视化 / 史实细节；

就应该停止研究，避免“研究作为拖延”。
